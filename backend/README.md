# CashGuard — выявление нарушений кассовой дисциплины по видео

Сервис принимает видеозапись кассы, находит визуально наблюдаемые признаки возможных нарушений и возвращает таймкод, кадры-доказательства, описание и ссылку на пункт нормативного акта РК. Все модели работают локально, без облачных AI-сервисов.

## Архитектура

```
видео ─► ffmpeg: кадры 2 fps, 336 px ─► окна по 8 с (шаг 6 с)
      ─► VLM (Qwen3.5-9B, llama.cpp): по каждому правилу вопрос «да/нет»
         вероятность берётся из logprobs ответа, а не из текста
      ─► оценка правила = его вероятность минус средняя по всем правилам в этом окне
      ─► для правил выше порога: вопрос «в каком кадре» (буква кадра, тоже по logprobs)
      ─► детектор RT-DETRv2 на тех же кадрах: люди и ноутбук → зона стола,
         моменты ухода и промежутки, когда у стола никого нет
      ─► D-03, A-04 засчитываются только около ухода, таймкод = момент ухода
      ─► A-01 = стол пуст + «на экране рабочее окно» по увеличенному фрагменту экрана
      ─► OWLv2 (поиск по тексту) находит сейф; фрагмент сейфа каждые 3 с:
         D-02 = дверца открыта на 3 фрагментах подряд (≈ 6–9 с), а не мельком
      ─► слияние событий, пороги по правилам (rules/thresholds.json)
      ─► короткое описание видимых действий + кадры t, t±1 с
      ─► пункт нормы из каталога rules/catalog.json (модель ссылки не пишет)
```

Ключевые решения:
- **Вероятности вместо самооценки.** Модель отвечает одним токеном `yes/no`, уверенность — `p(yes) / (p(yes)+p(no))` из logprobs. Самооценка модели в тексте («уверенность 0.95») оказалась некалиброванной.
- **Поправка на уклон окна.** На «насыщенных» окнах Qwen3.5-9B отвечает «да» почти на все правила сразу. Вычитание средней вероятности окна оставляет только то, что выделяется на фоне остальных правил (`SCORE_NORM=window`, по умолчанию; `none` — сырые вероятности). На 40 роликах это подняло точность leave-one-out с 0.675 до 0.725 и совпадение типа с 5/16 до 8/17.
- **Детектор вместо «кассира нет» от модели.** Момент ухода и пустой стол даёт RT-DETRv2 по каждому кадру; зона стола строится по найденному ноутбуку, без ручной разметки ракурса. Если ноутбук не найден, правила ухода не фильтруются, а A-01 не проверяется.
- **Фрагмент экрана для A-01.** На целом кадре экран ноутбука занимает 1–2 токена изображения, на увеличенном фрагменте — сотни: 9B уверенно отличает рабочее окно от экрана блокировки (0.96 против 0.04 на паре X-28/X-29). Вместе с детектором это подняло leave-one-out до 0.800 (18 из 21 найдено, 5 ложных из 19).
- **Сейф по фрагменту для D-02.** Сейфа нет среди классов RT-DETRv2, поэтому его находит OWLv2 по тексту «a metal cabinet» на 5 кадрах; берётся рамка, которая стоит на одном месте во всех кадрах (человек за стеклом двигается, сейф — нет). Открытый мельком сейф (кладут или берут) не считается: нужна открытая дверца на 3 фрагментах подряд. Leave-one-out вырос до 0.825.
- **Запас порога 0.02.** Повторный прогон llama.cpp сдвигает оценки примерно на ±0.02, поэтому порог стоит на 0.02 выше максимума чистых роликов (`calibrate.py --margin 0.02`).
- **Ссылки только из каталога.** Модель выбирает правило, а документ, пункт и требование подставляются из `rules/catalog.json`. Выдуманных ссылок быть не может.
- **Пороги по правилам** подбираются по роликам без нарушений (`eval/calibrate.py`): порог правила — чуть выше максимума его оценки на «чистых» видео. Это прямо ограничивает ложные срабатывания.
- **Дедлайн 270 с** от момента загрузки: если не успеваем, возвращаем найденное по просмотренной части, а не таймаут.
- **Без распознавания лиц.** Модель видит людей только как «кассир», «клиент», «посторонний».

## Модели

| Компонент | Модель | Лицензия |
|---|---|---|
| VLM | Qwen3.5-9B, GGUF Q4_K_M + mmproj BF16 | Apache 2.0 |
| Инференс | llama.cpp `llama-server` (OpenAI-совместимый API) | MIT |
| Детектор людей и ноутбука | RT-DETRv2 r50 (`PekingU/rtdetr_v2_r50vd`), transformers + torch | Apache 2.0 / BSD |
| Поиск сейфа по тексту | OWLv2 (`google/owlv2-base-patch16-ensemble`) | Apache 2.0 |

## Запуск локально (macOS, Apple Silicon)

```bash
llama-server -m Qwen3.5-9B-Q4_K_M.gguf --mmproj mmproj-Qwen3.5-9B-BF16.gguf \
  --port 8081 -c 32768 -np 2 --image-max-tokens 256 --reasoning off
uv venv --python 3.11 && uv pip install -r pyproject.toml
DETECTOR=off API_KEY=<ключ> .venv/bin/uvicorn app.main:app --port 8000
```

Без torch детектор выключается через `DETECTOR=off`; с ним — `uv pip install -r pyproject.toml --extra detector`. Пороги в `rules/thresholds.json` подобраны для режима с детектором.

Интерфейс: `http://localhost:8000`.

## Запуск на GPU-сервере

Веса (`Qwen3.5-9B-Q4_K_M.gguf`, `mmproj-Qwen3.5-9B-BF16.gguf`) положить в `./models`, затем:

```bash
API_KEY=<ключ> docker compose up -d --build
```

После загрузки весов интернет для обработки видео не нужен: веса детекторов скачиваются при сборке образа, в работе стоит `HF_HUB_OFFLINE=1`.

Без Docker (как на L4): `deploy/gpu_setup.sh` ставит llama.cpp, веса и Python-окружение, `START_APP=0 deploy/gpu_start.sh` поднимает llama-server, `API_KEY=<ключ> deploy/install_service.sh` ставит API как systemd-сервис `cashguard` с автоперезапуском (ключ хранится в `.env` с правами 600).

`deploy/gpu_start.sh` запускает llama-server с `--cache-ram 1024`: по умолчанию кэш промптов в оперативной памяти растёт до 8 ГБ и вместе с контрольными точками гибридной модели заполняет 16 ГБ машины.

## API

Все запросы с заголовком `X-API-Key`.

```bash
curl -X POST https://<host>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
curl https://<host>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ответ `/api/v1/jobs/{job_id}` строго по схеме ТЗ, без лишних полей: `job_id`, `status`, `verdict`, `violations[].type/timecode_sec/description/evidence_frames`. В `description` — что видно на видео и основание: полное название документа, пункт и требование. Пока задача идёт, есть ещё `progress`.

Для интерфейса без ключа: `POST /ui/analyze`, `GET /ui/jobs/{job_id}` (то же плюс `rule` с документом, пунктом и ссылкой на adilet.zan.kz, `confidence`, `elapsed_sec`), `GET /ui/jobs/{job_id}/video`. Если фронтенд открыт с другого адреса, разрешите его: `CORS_ORIGINS=https://front.example.kz`. Папка `static/` необязательна: если её нет, сервис отдаёт только API.

Проверка развёрнутого сервиса по контракту (ключ, коды ошибок, строгая схема, JPEG-кадры, лимит 5 минут):

```bash
API_KEY=<ключ> .venv/bin/python eval/check_api.py --base https://<host> video1.mov video2.mov
```

Время обработки: одно видео до 145 с — около 200 с на L4; пять типичных роликов датасета одновременно — 150–180 с. Каждая задача получает не больше окон в очереди к модели, чем у неё слотов, поэтому одновременные задачи идут вперемешку. Если к дедлайну (270 с) не успеваем, пропускаются окна через одно по всему видео, а не конец ролика; жёсткий предел задачи — 295 с, после него `failed`.

## Оценка качества

```bash
.venv/bin/python eval/run_eval.py --out runs/eval/catalog   # оценки по окнам, кэш по роликам
.venv/bin/python eval/run_detector.py --frames-from runs/eval/catalog
.venv/bin/python eval/run_facts.py --out runs/eval/facts_v2
.venv/bin/python eval/calibrate.py --run runs/eval/catalog --detect runs/eval/detect \
  --facts runs/eval/facts_v2 --margin 0.02 --write rules/thresholds.json
```

`calibrate.py` печатает качество in-sample и leave-one-out (каждый ролик оценивается порогами, подобранными без него).

## Ограничения

- Модель видит кадры с частотой 2 fps; очень быстрые действия рук могут быть пропущены.
- Не проверяется то, что не видно на видео: проводки, сверки, содержимое документов.
- Таймкод — момент, когда признак впервые хорошо виден, а не начало действия.
